# أساس المجتمع: الحفظ والبلاغات — 0.15

هذه الدفعة تضيف حفظ البطاقات المشتركة للمستلم والإبلاغ والمراجعة التشغيلية إلى روابط 0.13. **لا تنفذ موجزًا اجتماعيًا أو متابعة وتعليقات أو عضوية دفاتر تعاونية.**

## حفظ نسخة للمستلم

افتح رابط البطاقات وأنت مسجل الدخول في علامة التبويب نفسها. يظهر مربع موافقة قبل «حفظ البطاقات في مكتبتي». للزائر غير المسجل تعليمات للعودة لمساحة الدراسة وتسجيل الدخول ثم فتح الرابط مجددًا في نفس التبويب؛ لا يُرسل رمز جلسة المستخدم مع القراءة العامة أو التصحيح. يرسل فقط مع الحفظ والإبلاغ اللذين يحتاجان حسابًا.

ينشئ الحفظ دفترًا خاصًا جديدًا ومجموعة بطاقات جديدة بمعرفات جديدة للمستلم، مع النص المنشور فقط و`origin=shared` و`reference=null`. لا ينسخ المصدر أو رابطه أو معرفه، ولا تقدم الطالب أو مواعيد مراجعته. في الواجهة علامة «نسخة مشتركة · غير مدققة». هذه البطاقات ليست مصادر RAG؛ الدفتر الجديد بلا مصادر حتى يرفع المستلم مصادره الخاصة. يمكن تعديل البطاقات ومراجعتها وإنشاء اختبارات منها بالأدوات القائمة.

- يلزم أن تكون المشاركة فعالة وبطاقات وليست اختبارًا. الصلاحيات تشمل جلسة المستلم وقدرة الرابط، لا جلسة الناشر.
- لا يوجد تحديث تلقائي أو صلاحيات مشتركة مع الأصل. **إلغاء الرابط أو حذف حساب الناشر/دفتره لا يمحو النسخة المستقلة عند المستلم.** موافقة الناشر توضّح إمكانية الاحتفاظ بالنسخة. لا توجد أداة لسحب النسخ أو إزالة محتوى من دفاتر المستلمين جماعيًا.
- تطبق حصة الدفاتر العامة؛ لا ينشأ دفتر جزئي عند تجاوزها أو فشل transaction.
- يحتاج الطلب UUID. إعادة الطلب بنفس المستخدم والمعرف والرمز تعيد معرفي النسخة السابقة دون تكرار حتى إن أُلغي الرابط لاحقًا؛ اختلاف الرمز يرجع 409. الواجهة تحتفظ بالمعرف عند إعادة المحاولة داخل المكون. إعادة تحميل الصفحة أو فتح رابط جديد قد يولد معرفًا جديدًا ويسمح بنسخة أخرى؛ الحفظ ليس dedup عالميًا للمحتوى.
- لا يُحفظ رمز الرابط الخام؛ فقط تجزئته في سجل إعادة الطلب. حذف دفتر المستلم يحذف البطاقات وسجل الاستيراد؛ حذف حسابه يشمل كل نسخه.
- ليست النسخة دليلًا على جودة المحتوى أو ترخيصه؛ يلزم حق الاحتفاظ واستخدام النص. الاستيراد لا يثبت حقوق الناشر آليًا.

## البلاغات

الحساب المسجل الذي يحمل رابطًا فعالًا يستطيع إرسال سبب من: privacy / copyright / harmful / incorrect / spam. لا يوجد حقل نص حر أو رفع أدلة في هذه النسخة لتقليل إرسال بيانات حساسة. بلاغ واحد لكل حساب ورابط، وإعادة الإرسال تعيد استلامًا عامًا دون كشف سجل البلاغ. لا تعيد إعادة الإرسال فتح بلاغ حُسم. الحد 20 بلاغًا معلقًا لكل مُبلّغ، مع حدود POST العامة أيضًا. لا توجد تكلفة تحقق هوية قوية أو منع حسابات متعددة؛ هذه ليست منظومة مكافحة إساءة مكتملة.

رد API العام لا يكشف معرف البلاغ أو اسم المُبلّغ للناشر، ولا يعرض قائمة بلاغات له. البلاغ **ادعاء يحتاج مراجعة**، وليس إثبات مخالفة أو تصحيحًا علميًا أو وعدًا بإزالة فورية. لا تخفي كثرة البلاغات الرابط آليًا. لا يوجد حظر مستخدم أو إيقاف إعادة النشر أو إجراء على جميع نسخ المحتوى بعد.

### أداة المشغّل

الأداة CLI فقط، وتتطلب وصولًا موثوقًا لقاعدة البيانات. لا يوجد endpoint إداري أو مفتاح مشرف في المتصفح. شغّل من جذر المستودع مع `PYTHONPATH=backend` و`DATABASE_URL` مضبوط صراحة من بيئة تشغيل آمنة:

```sh
PYTHONPATH=backend .venv/bin/python -m knowlm.moderation pending
PYTHONPATH=backend .venv/bin/python -m knowlm.moderation show REPORT_ID
PYTHONPATH=backend .venv/bin/python -m knowlm.moderation dismiss REPORT_ID
PYTHONPATH=backend .venv/bin/python -m knowlm.moderation revoke REPORT_ID
```

استخدم معرفًا فعليًا من pending بدل REPORT_ID. القائمة تعرض أقدم 100 بلاغ معلق ومعرفه والسبب والتاريخ فقط. show يعرض **نص النسخة المنشورة** للمراجعة دون الرمز الخام أو هوية المبلّغ. لا تحفظ المخرجات في سجلات عامة. النص يطبع JSON escaped لتجنب تفسير حروف التحكم من المحتوى في الطرفية.

- dismiss يضع dismissed وتاريخ الحسم ويبقي الرابط متاحًا.
- revoke يضع actioned وتاريخ الحسم، ويلغي الرابط ويمحو نص نسخته بنفس transaction. القراءة والتصحيح والاستيراد الجديد تفشل بعده.
- الحسم لا يمكن تغييره بعملية ثانية على البلاغ نفسه. بلاغات أخرى على الرابط قد تبقى معلقة؛ لا تغلقها الأداة جماعيًا.
- إجراء المشغّل لا يمس النسخ التي حفظها مستلم سابقًا، ولا يمنع الناشر من إنشاء رابط جديد. صاحب وصول DB يستطيع أصلًا قراءة البيانات؛ ليست هذه بديلًا عن RBAC تشغيلي أو سجل تدقيق مستقل.
- لا يوجد فريق مراجعة أو SLA مضمّن في الكود. يلزم تكليف مشغل فعلي وسياسة حقوق/قُصّر وتصعيد واستئناف وإشعارات قبل الإطلاق العام.

## الخصوصية والاحتفاظ

يحفظ البلاغ معرف المُبلّغ والمشاركة والسبب والتاريخ والحالة وتاريخ الحسم، دون نسخة إضافية من النص أو عنوان IP في سجل البلاغ. قد تحتفظ حدود الطلبات بتجزئة IP وفق LIMITS.md. حذف حساب المبلّغ يزيل بلاغاته حتى على محتوى مستخدم آخر؛ حذف الدفتر/الحساب الناشر يزيل بلاغات مشاركاته. لا يُقدّم هذا كحفظ أدلة قانونية دائم. لا يوجد تنظيف دوري للبلاغات المحسومة أو سجل تدقيق خارجي؛ حدد سياسة احتفاظ قبل الإنتاج. النسخ الاحتياطية وسياسة providers خارج هذا الحذف كما توضح PRIVACY.md.

## API والترحيل والتحقق

- `POST /v1/shared/import`: جلسة bearer و`X-KnowLM-Share`، body `{request_id: UUID, consent: true}`، يرجع `{notebook_id, deck_id}` و201، حتى في replay.
- `POST /v1/shared/report`: الجلسة والـheader نفسه، body `{reason: enum}`، يرجع `{status: received}` و202.
- ردود المسارين تحمل no-store/noindex مثل بقية `/v1/shared/`، ولا ينبغي تسجيل header القدرة أو أجسام الاستجابات في تحليل خارجي.
- `alembic upgrade head` يطبق `8e9123697c5b` قبل إعادة تشغيل API. downgrade يسقط سجلات البلاغات وإعادة الاستيراد فقط؛ النسخ نفسها تبقى دفاتر للمستلم.

اختبارات SQLite تشمل العزل والموافقة وصلاحية الرابط ونوعه وإعادة الطلب المتزامنة وحصص الدفاتر والبلاغات والتراجع الذري وحذف سجلات المستخدمين وحسم البلاغ وCLI. React يغطي الموافقة وعدم إرسال جلسة المستخدم في القراءة العامة وإعادة UUID عند الفشل. اختبارا متصفح حقيقيان (هاتف/كمبيوتر) يحفظان نسخة بحساب مستلم ويبلغان ثم يحذفان أصل الناشر ويتحققان من استمرار النسخة وعدم الوصول لمصادره. لا توجد اختبارات حمل PostgreSQL أو تقييم عمليات إشراف بشرية واقعية بعد.
