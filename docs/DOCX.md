# مستندات Word — 0.9

من «إضافة مصدر» اختر Word ثم ملفًا بصيغة `.docx`. يُحفظ طلب المعالجة في قاعدة البيانات ويعالجه العامل المنفصل. تظهر الحالة وإعادة المحاولة في قائمة المصادر مثل PDF. يصبح النص متاحًا للأسئلة والبطاقات والاختبارات والمخرجات والخرائط بعد نجاح الاستخراج فقط.

## ما يُستخرج

- متن `word/document.xml`، بما فيه فقرات خلايا الجداول بالترتيب البنيوي، والنص العربي والإنجليزي وعلامات التبويب وفواصل الأسطر.
- لكل فقرة رقم تسلسلي ضمن المتن المستخرج، بما فيه الفقرات الفارغة. الفراغ لا يولّد مقطع بحث، لكنه لا يغير ترقيم ما بعده.
- مراجع `locator_type=paragraph` تحتوي `paragraph` و`page=null` وتفتح نص الفقرة عبر رابط API محمي. لا تمثل صفحات Word أو أرقام الفقرات المطبوعة في المستند. للتخزين الداخلي فقط يُعاد استخدام عمود chunk.page كرقم الفقرة؛ لا تغيير مخطط لهذه الدفعة.
- لا نستخرج الصور أو OCR أو الحواشي والرؤوس والتذييلات والتعليقات أو مربعات النص/الرسوم والمرفقات. يُهمل النص المحذوف بتعقب التغييرات وأكواد الحقول؛ يظهر نص النتائج المكتوب، ولا تُنفذ الحقول أو الروابط. قد يختلف النص عن العرض النهائي في Word، خاصة مع التخطيطات المعقدة.
- يدعم OOXML المعتاد ذي namespace الانتقالي؛ صيغة Strict وDOC القديم وDOCM وGoogle Docs المباشر غير مدعومة. يمكن تصدير Google Docs إلى DOCX ثم رفعه، لكن ذلك ليس تكامل صلاحيات مع Google.

## حدود وحماية

10 MiB للرفع، 1000 عنصر ZIP، 25 MB إجمالي حجم معلن بعد فك الضغط، 5 MB لأي عنصر، ونسبة ضغط لا تتجاوز 200:1. يُرفض تكرار أسماء ZIP والتشفير والماكرو. الملف لا يُفك إلى مجلد ولا تُفتح علاقاته الخارجية. XML يُحلل بـdefusedxml مع منع DTD والكيانات الخارجية. هذه حدود تحفظية قد ترفض بعض الملفات السليمة الكبيرة أو عالية الضغط.

الاستخراج في عملية فرعية بمهلة 30 ثانية، وحد ذاكرة 512 MiB وCPU لمدة 20 ثانية على Linux؛ حتى 5000 فقرة و500 ألف محرف. هذه ليست sandbox أمنية كاملة: الإنتاج يحتاج حاوية دون شبكة بصلاحيات ملفات محدودة وحصص ومحدد معدل. لا يوجد فحص مكافحة فيروسات شامل.

الحمولة الخام خاصة في قاعدة البيانات، وتُحذف بعد نجاح الاستخراج. تبقى عند الفشل لإعادة المحاولة ضمن الحد الحالي للمهام (حتى 3 محاولات). لا توجد سياسة تنظيف تلقائي للملفات الفاشلة أو حذف شامل للمستخدم بعد؛ يجب إضافتها قبل الإطلاق العام.

## API والتشغيل

- `POST /v1/notebooks/{id}/sources/docx-jobs` برفع multipart باسم `file` يعيد 202 ومعرّف المصدر والمهمة.
- `GET /v1/jobs/{id}` و`POST /v1/jobs/{id}/retry` محميان بملكية الدفتر.
- مراجع الأسئلة والتعلم تفتح `GET /v1/notebooks/{id}/sources/{source_id}/paragraphs/{number}`. مسار `/pages/{number}` القديم يعمل كاسم بديل داخلي، لكنه يعيد `page=null` لمصدر DOCX.
- حدّث `backend/requirements.txt` ثم أعد تشغيل API والعامل. لا ترحيل جديد؛ نوع المصدر محفوظ كسلسلة نصية.

الاختبارات تستخدم مستندات صغيرة مولّدة، تشمل العربي والجداول والفراغات وأخطاء ZIP/XML وحدود الموارد والملكية والمراجع وحفظ المحادثة. اختبارا Chromium للهاتف وسطح المكتب يغطيان الرفع والمعالجة والسؤال والمرجع وإعادة التحميل. يلزم تقييم ملفات Word واقعية مرخّصة قبل اعتبار التغطية شاملة.
