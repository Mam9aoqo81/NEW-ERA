# مؤقت المذاكرة المشترك — 0.23

## الاستخدام

داخل الدفتر افتح «التعاون وغرفة الدفتر»، ثم «مؤقت Pomodoro المشترك 25/5». يعمل أيضًا في دفتر شخصي بلا دعوة. كل الدفتر له مؤقت واحد يراه الأعضاء المصرح لهم:

- المالك والمحرر: بدء/إيقاف مؤقت/إعادة ضبط الفترة. إعادة الضبط تؤثر على جميع الأعضاء وتحتاج تأكيد واجهة.
- القارئ: مشاهدة الوقت والحالة فقط؛ يرفض الخادم محاولات التحكم حتى لو أرسلها مباشرة.
- نهاية 25 دقيقة عمل تتوقف عند صفر، ثم زر «الفترة التالية» يجهز 5 دقائق راحة. بدء الفترة الجديدة يدوي. عند نهاية الراحة يمكن تجهيز 25 دقيقة عمل جديدة بالطريقة نفسها.
- الإغلاق وتحديث الصفحة لا يوقفان المؤقت المشترك ولا يعيدان عدّه. الوقف المؤقت الخادمي يثبت الوقت المتبقي للجميع.

**هذا جزء المؤقت من غرف المذاكرة وليس غرفة اتصال صوت/فيديو.** لا WebRTC أو ميكروفون/كاميرا أو حضور أو بث أو تنبيهات خلفية. لا انتقال تلقائي للمراحل أو احتساب حضور/دورات تركيز/تقييم إنتاجية، ولا وعد بتنبيه حين يكون التبويب مغلقًا.

## التزامن والصلاحيات

الخادم يحفظ نهاية الفترة بتوقيت UTC، لا نبضات عداد العميل. الواجهة تجلب الحالة كل 5 ثوانٍ أثناء الظهور، وتستعمل performance.now للعرض بين الطلبات مع تعويض تقريبي لنصف رحلة الشبكة. تعيد المزامنة عند عودة التبويب. لا نعتمد على تطابق ساعة جهاز الطالب مع الخادم، لكن التزامن تقريبي ويعتمد على تأخير الشبكة وساعة خوادم النشر؛ اضبط NTP قبل تعدد نسخ API.

كل تعديل يحمل version من آخر حالة، ويُسلسل بقفل صف الدفتر ثم إعادة فحص العضوية. تعارض 409 لا يكتب فوق قرار عضو آخر. الواجهة تخفي الحالة القديمة عند الفشل وتعيد جلب الحالة؛ انقطاع الاستجابة لا يعني أن الطلب لم يُنفّذ. لا إعادة محاولة POST آلية. الرد القديم ذو الإصدار الأقل لا يكتب فوق الأحدث.

المؤقت لا يحفظ اسم من ضغط الزر أو سجل حضور. رفع/خفض/إزالة العضوية يسري على الطلب التالي؛ poll ليس إذنًا دائمًا. القارئ السابق قد يحتفظ بلقطة للحالة كما في بقية بيانات الدفتر. إزالة عضو لا تعيد مؤقت بقية الأعضاء. حذف الدفتر أو حساب المالك يمحو صف المؤقت ضمن الحذف الذري. النسخ الاحتياطية مستثناة وفق PRIVACY.md.

## API والترحيل

- `GET /v1/notebooks/{id}/pomodoro`: جلسة وصلاحية قراءة. الدفتر دون مؤقت يرجع work/1500 ثانية/version=0 دون إنشاء صف. الرد no-store.
- `POST` المسار نفسه: `{action:"start"|"pause"|"reset"|"next",version:integer}`. صلاحية مالك/محرر؛ لا حقول إضافية أو ثوانٍ من العميل. `next` متاح فقط بعد انتهاء الفترة؛ لا ينتقل تلقائيًا. `reset` يضبط مدة الفترة الحالية (عمل أو راحة) ولا يبدأها.
- الرد: phase/running/finished/remaining_seconds/version/server_now/ends_at/can_control. انتهاء الموعد ظاهر في القراءة دون كتابة دورية أو زيادة version. المؤقت المتوقف لا يتناقص.
- حدود mutations القائمة تنطبق على التحكم. لا يوجد سجل تدقيق إداري أو قفل يمنع محررًا مصرحًا له من العبث بالمؤقت؛ على المالك خفض صلاحياته عند الحاجة. GET الدوري ليس تقييم حمل إنتاجيًا.
- الترحيل `ba81399136aa` بعد `c6ad94578fb7` يضيف notebook_focus_timers. أوقف API، نفذ `alembic upgrade head` ثم أعد تشغيله. downgrade يسقط المؤقتات فقط ولا يغير الدفاتر أو العضويات.

## القبول

اختبارا Backend يغطيان ساعة خادم متحكمًا فيها لدورة 25/5 كاملة، الوقف والاستئناف وعدم الانتقال التلقائي والتعارض والعزل وسحب العضوية والتحقق والحذف. ثلاثة React للتشغيل بالإصدار المرصود، وعدم عرض التحكم للقارئ، وإخفاء الحالة المتعارضة. اختبار متصفح فعلي بحسابين مستقلين على مقاسي الكمبيوتر/الهاتف يبدأ ويوقف ويرى القارئ التغيير ويعيد التحميل ويفحص استمرار الوقت وحدود الصلاحيات.

الجولة الكاملة: **232 Backend ناجحًا وواحد متخطى، 64 Frontend، 32 اختبار متصفح ناجحًا**. بناء الإنتاج والتنسيق وAlembic check وgit diff check ناجحة. لا اختبار انتظار حقيقي 25 دقيقة؛ انتقال المراحل اختُبر بساعة محاكاة، والتزامن والحفظ اختُبرا بخوادم ومتصفحات حقيقية محليًا. لم يُختبر حمل PostgreSQL أو Safari/أجهزة فعلية.
