# OCR محلي للـPDF المصوّر — 0.16

## النطاق المنفّذ

مسار محلي اختياري لقراءة صفحات PDF التي لا تحتوي نصًا مستخرجًا، باستخدام PDFium للرسم وTesseract 5 عبر tesserocr ونموذجي `ara+eng` من tessdata_fast. لا يُرسل الملف أو صوره لخدمة OCR خارجية، ولا تُنزّل نماذج أثناء طلب المستخدم. الدفعات الدائمة وإعادة المحاولة والصلاحيات والحذف تظل ضمن عامل المعالجة القائم.

يفحص pypdf النص الأصلي أولًا لكل صفحة. الصفحات التي بها أي نص لا تعاد قراءتها آليًا؛ لذلك **قد يفوّت المسار صورًا داخل صفحة ذات عنوان نصي أو OCR قديمًا معطوبًا**. الصفحات الفارغة بلا نص تمر أيضًا بمحاولة OCR. لا توجد معالجة مستقلة لملفات PNG/JPEG أو دوران تلقائي مضمون أو خط يد أو ترميم صور أو استخراج جداول/معادلات/أعمدة بترتيب دلالي.

## الإعداد

من جذر المستودع، بعد تثبيت المتطلبات الأساسية وتشغيل الترحيلات:

```sh
.venv/bin/pip install -r backend/requirements-ocr.txt
PYTHONPATH=backend .venv/bin/python -m knowlm.ocr_models --directory backend/data/tessdata
export KNOWLM_OCR_ENABLED=1
export KNOWLM_OCR_DATA_PATH="$PWD/backend/data/tessdata"
.venv/bin/alembic upgrade head
```

أعد تشغيل **API والعامل** بالمتغيرات نفسها. الإعداد الافتراضي معطل؛ عند تعطيله يرجع PDF المصوّر بالكامل `ocr_required` ولا تجرى محاولة OCR. إذا فُعّل دون مكتبات/نماذج، يظهر فشل إعداد عام ولا يُعتبر الملف جاهزًا. `ocr_enabled` في `/health` يعكس تفعيل إعداد API فقط، وليس فحص جاهزية نماذج العامل؛ لا تستخدمه وحده كفحص صحة تشغيلي.

على Linux x86_64 اختُبرت wheels المحددة في `requirements-ocr.txt`. منصات أخرى قد تحتاج بناء tesserocr واعتماديات Tesseract/Leptonica من المصدر؛ لا ندّعي دعمها دون اختبار. التشغيل يحتاج ملفات النماذج محليًا ومسارًا مقروءًا. لا تضعها في Git أو داخل web public directory. `backend/data` مستثنى أصلًا من التتبع.

أداة `ocr_models` **إجراء صريح للمشغّل فقط**. تنزّل ملفين من GitHub API عبر TLS، بمعرفي Git blob ثابتين وتتحقق من SHA-256 قبل الاستبدال الذري. الملفات الصحيحة الموجودة لا يعاد تنزيلها؛ لا يُستبدل الملف ببيانات فشلت مطابقة تجزئتها. لا ترسل مفاتيح GitHub أو أي ملفات للمستخدم. قد تتأثر بحدود GitHub API أو الشبكة. يمكن للمشغّل توفير نفس الملفات يدويًا بعد التحقق من التجزئات:

## الحدود والقراءة غير الموثوقة

- الحدود العامة: 10 MiB و200 صفحة و500,000 حرف مستخرج.
- حتى **10 صفحات بلا نص** تحتاج محاولة OCR في الملف الواحد، بما فيها الصفحات البيضاء؛ رفض العدد الزائد قبل رسم الصفحات، لا اقتطاع صامت.
- رسم grayscale عند 200 DPI، حتى 12 مليون pixel للصفحة، وأي بُعد حتى 10,000 pixel؛ يتحقق الحجم قبل الرسم. الحجم الطبيعي الكبير أو نسخة منخفضة الجودة قد يتطلبان تقسيم الملف أو تحسين المسح.
- عملية الاستخراج حين OCR مفعّل محدودة بـ1 GiB address space و45 ثانية CPU و60 ثانية wall clock؛ حد OpenMP thread واحد. هذه حدود الملف كاملًا وليست لكل صفحة. lease العامل 90 ثانية وتظل حواجز النشر stale-worker fencing قائمة.
- متوسط ثقة Tesseract أقل من 40 عند إرجاع نص غير فارغ يرفض الملف كله بـ`ocr_low_confidence`، دون نشر نص جزئي. هذا حد تجريبي **ليس نسبة صحة 40% أو ضمانًا**. قد يخطئ المحرك بثقة مرتفعة، أو يرجع نصًا فارغًا لصفحة غير فارغة فتظل بلا مقاطع.
- الصفحة البيضاء بلا نص OCR تبقى في موضعها في القائمة؛ الصفحات لا تُضغط أو تُعاد ترقيمها. لو بقي الملف كله بلا نص يظهر `ocr_required`.
- الموارد المحدودة ليست sandbox أمنيًا. المكتبات native تتعامل مع ملفات غير موثوقة؛ يلزم عزل حاوية/نظام ملفات وشبكة وأسرار وصلاحيات منخفضة ومراقبة تحديثات أمنية قبل الإنتاج. المتطلبات الاختيارية منفصلة ولا يشملها npm audit.

## الاستشهادات والخصوصية

يُحفظ `sources.ocr_pages` كقائمة أرقام الصفحات التي نتج منها نص OCR فعلي. الصفحات النصية أو البيضاء لا تأخذ علامة OCR. معرف المصدر وأرقام الصفحات والملكية لا تتغير. تتضمن استشهادات الأسئلة ومراجع البطاقات/المخرجات المرتبطة بالصفحة `ocr=true`، وتحفظ العلامة في تاريخ الإجابة. قارئ الاستشهاد يحذر من أخطاء الأرقام والتشكيل والجداول ويطلب مراجعة الأصل.

هذه **مراجع صفحة** وليست bounding boxes للكلمات. القارئ يعرض النص المستخرج لا الصورة الأصلية، ولا يوجد إبراز على أصل PDF أو واجهة تصحيح OCR بعد. النص يصبح مصدرًا قابلًا للبحث والتوليد كغيره؛ جودة الاسترجاع لا تصلح أخطاء OCR تلقائيًا.

لا تحفظ صور الصفحات على القرص أثناء المعالجة؛ bitmap والصورة يغلقان بعد كل صفحة. الملف الخام يظل payload للعمل الدائم حتى النجاح أو الحذف، وفق سياسة المعالجة الحالية؛ يُمحى من السجل النشط بعد النجاح، بينما payload الفاشل يحتفظ به لإعادة المحاولة حتى الحذف. النص والـmetadata يحذفان مع المصدر/الدفتر/الحساب وفق الخصائص القائمة؛ لا يعني ذلك محوًا آمنًا من صفحات SQLite أو WAL أو backups أو ذاكرة العملية. انظر PRIVACY.md.

ترحيل `294375eff605` يضيف عمودًا nullable دون تغيير نصوص المصادر الموجودة. لا حاجة لإعادة OCR للمصادر النصية السابقة. ترجيع الترحيل يزيل metadata OCR دون إزالة النص؛ سيفقد النص المحفوظ علامة التحذير، لذلك لا ترجعه دون خطة للتعامل مع المصادر المقروءة آليًا.

## التحقق الفعلي وحدوده

اختُبر المحرك المحلي الحقيقي Tesseract 5.5.4 مع النموذجين المذكورين على fixture مؤلّف ذاتيًا: صفحة بيضاء ثم صورة بها جملتان عربية وإنجليزية، بلا طبقة نص PDF. قُرئت الجملتان، وظل الاستشهاد في الصفحة الثانية، وفُرض عزل المصدر عن حساب ثانٍ. اختبارات Chromium للهاتف والكمبيوتر رفعت الملف عبر الواجهة، وانتظرت العامل الحقيقي، وسألت بالعربية، وفتحت المرجع وتحذير OCR، وتحققت من حفظ التحذير بعد reload. ليست هذه محاكاة للمحرك.

لتشغيل اختبارات المحرك مع النماذج المثبتة:

```sh
PYTHONPATH=backend KNOWLM_TEST_OCR_DATA_PATH="$PWD/backend/data/tessdata" .venv/bin/pytest -q backend/tests
```

بدون المتغير يتجاوز pytest الاختبارين المحتاجين للنماذج ويشغّل بقية اختبارات العقد والموارد. اختبارات OCR بالمتصفح تتجاوز نفسها إذا كان `ocr_enabled` غير مفعّل؛ جهّز العامل والنماذج أيضًا لتشغيلها فعليًا.

**لا توجد بعد دراسة دقة WER/CER مستقلة على مسوح واقعية متنوعة أو تقييم خط يد/جداول/مناهج، ولا اختبار native على منصات أخرى أو حمل إنتاجي.** لا تصف العينة الواضحة بأنها إثبات جودة عامة للـOCR العربي. بقية Smart Canvas وخط اليد متبقية.
