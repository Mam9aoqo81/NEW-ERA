# حذف الدفتر وحدود الاحتفاظ — 0.10

## الاستخدام

من رأس الدفتر اضغط «حذف الدفتر» ثم اكتب اسم الدفتر كما هو لتفعيل «حذف الدفتر نهائيًا». يمكن الإلغاء دون إرسال طلب. عند النجاح يغلق الدفتر وتنتقل الواجهة لدفتر آخر أو شاشة إنشاء أول دفتر. إذا ضاع رد الحذف بعد التنفيذ تتحقق الواجهة من قائمة الدفاتر قبل إظهار خطأ وإبقاء مساحة قديمة مفتوحة.

`DELETE /v1/notebooks/{id}` يتطلب جلسة صالحة وملكية الدفتر. يعيد 204 عند النجاح، و404 لدفتر غير موجود أو مملوك لشخص آخر، و401 دون جلسة. إعادة الطلب بعد نجاح الحذف تعيد 404؛ لا يُنشأ سجل محتوى للاحتفاظ بنسخة محذوفة بغرض idempotency. كتابة الاسم تأكيد في الواجهة، وليست بديلًا عن تحقق الملكية على الخادم.

## ما يُحذف

داخل transaction واحدة، تُحذف سجلات الدفتر في قاعدة البيانات النشطة:

- مهام الاستيراد بما فيها حمولة الملفات الخام، pending/processing/failed/completed.
- المصادر والمقاطع المستخرجة، وسجل المحادثة ونسخ الإجابات والاستشهادات.
- مجموعات البطاقات وبطاقاتها بما فيها المحذوفة منطقيًا، وحالات المراجعة وأحداثها.
- الاختبارات ولقطات أسئلتها ومحاولاتها ونتائجها.
- المخرجات المحفوظة والخرائط واقتباساتها.
- الدفتر نفسه؛ لا يُحذف الحساب أو الجلسات أو أي دفتر آخر.

الحذف بترتيب الأبناء قبل الآباء دون تغيير المخطط. تفعيل foreign keys في اتصالات SQLite للتطبيق والعامل يمنع كتابة سجلات يتيمة بعد حذف الأصل. PostgreSQL يفرض قيود المخطط أصلًا، لكنه لم يُختبر فعليًا هنا.

## العامل والطلبات المتزامنة

يُحذف سجل المهمة أولًا. يراجع العامل رمز الحجز ووجود المهمة عند نشر النتائج، فلا يعيد إنشاء نص لمهمة محذوفة. يتحمل اختفاء المهمة أو المصدر بعد حجزها. فشل أي خطوة في الحذف يلغي transaction كلها.

أي عملية كتابة متأخرة من جلسة أخرى تبقى محكومة بقيود المراجع؛ قد تفشل بدل إتمام الطلب. هذا ليس إلغاءً عامًا للطلبات المتزامنة أو ضمان معالجة سلسة لكل أخطاء السباق. حذف سجل المهمة لا يقتل عملية الاستخراج الفرعية التي بدأت أصلًا: قد تحتفظ بالنص في الذاكرة حتى خروجها/انتهاء مهلتها، لكنها لا تنشره في قاعدة البيانات بعد الحذف. طلب مزود LLM أو YouTube بدأ بالفعل قد يستمر لدى الطرف الخارجي، ولا يضمن الحذف إيقافه أو محو بياناته.

## ما لا يضمنه الحذف

- ليس محوًا جنائيًا أو تشفيريًا لصفحات SQLite الحرة أو WAL أو وسيط التخزين.
- لا يمحو النسخ الاحتياطية أو سجلات النشر الخارجية أو نسخًا سبق تنزيلها أو استشهادات ما زالت في ذاكرة تبويب آخر. إعادة تحميل التبويب لا تعيدها من API.
- لا يوجد حذف حساب شامل أو سياسة تلقائية لتنظيف الحمولات الفاشلة أو إدارة النسخ الاحتياطية بعد.
- قبل الإطلاق يجب تحديد احتفاظ معلن للنسخ الاحتياطية والسجلات ومزوّدي AI، وحدود استعمال وتزامن، واختبار PostgreSQL تحت حمل. لا تجعل هذه الخاصية المنتج متوافقًا تلقائيًا مع تشريع خصوصية معين.

## التحقق

اختبارات الخادم تغطي بيانات التعلم والمحادثات والحمولات، وعزل المستخدمين والدفاتر الأخرى، والتراجع الكامل عند حقن فشل، واستخراجًا يبدأ قبل الحذف ثم يحاول النشر بعده، ورفض كتابة مرجع لأصل محذوف. اختبارات الواجهة تغطي التأكيد والإلغاء وفشل الخادم وضياع رد النجاح. اختبارا متصفح Word على الهاتف والكمبيوتر ينتهيان بحذف الدفتر ثم إعادة التحميل والتحقق من غيابه. لا تمثل هذه الاختبارات تدقيقًا أمنيًا مستقلًا أو إثبات مسح التخزين.
