# مشاركة البطاقات والاختبارات — 0.13

## طبيعة المشاركة

نسخة ثابتة برابط غير مُدرج، وليست فتحًا للدفتر ولا موجزًا اجتماعيًا. يمكن لأي شخص يحمل الرابط قراءتها دون حساب وتمريرها أو نسخها. لا توجد عضوية للمستلمين أو كلمة مرور للرابط أو مزامنة تعديلات أو استيراد لدفتر الزائر حاليًا.

من أدوات الدراسة اختر مجموعة بطاقات أو اختبارًا محفوظًا، ثم «مشاركة البطاقات/مشاركة الاختبار». تظهر معاينة لكل النص الذي سيُنشر، وعنوان مستقل عن اسم الدفتر، وصلاحية 1 أو 7 أو 30 يومًا. لا يُنشأ الرابط قبل تأكيد مراجعة النص وحق نشره. إذا تغير محتوى البطاقات منذ المعاينة يرفض الخادم النشر ويطلب تحديثها، بدل نشر نسخة لم يراجعها المستخدم.

الحدود: 1–50 بطاقة أو اختبار من حتى 20 سؤالًا، و20 رابطًا نشطًا لكل مستخدم. لا تُقتطع المجموعة بصمت إن كانت أكبر. لا يعدّ هذا حدًا إجماليًا للتخزين؛ النسخ المنتهية لا تُنظف تلقائيًا بعد.

## ما يُنشر وما يُحجب

- البطاقات: الوجه والظهر فقط.
- الاختبار: السؤال والاختيارات؛ بعد التسليم يظهر التصحيح والتفسير المخزنان في النسخة. ليس امتحانًا آمنًا؛ يستطيع حامل الرابط معرفة الإجابات بالتجربة.
- لا تُنشر تلقائيًا مراجع المصادر أو عناوين ملفاتها أو روابطها أو معرفاتها، ولا معرف الدفتر/المالك أو الجلسات أو جدولة الطالب ونتائجه. عرض الزائر يصرّح بأن المحتوى غير مدقق وأن المراجع الخاصة محذوفة.
- **قد يتضمن نص البطاقة أو السؤال أو التفسير نفسه معلومات خاصة أو اسم ملف أو رابطًا كتبه المؤلف.** إزالة حقول metadata ليست تنقيحًا ذكيًا لكل الأسرار. المعاينة والموافقة لا تعفيان المشغل أو الناشر من حقوق النشر والخصوصية. لا تنشر محتوى حساسًا أو لا تملك حق مشاركته.
- نتائج الزوار لا تُحفظ كـQuizAttempt؛ التصحيح بلا حساب ولا يغير تقدم صاحب النسخة. تنطبق حدود POST العامة على التصحيح، وقد يسجل مخزن الحدود تجزئة عنوان زائر دون نص إجاباته.

## الرابط والأمان

الرابط `/share#TOKEN` يحمل رمزًا عشوائيًا بقدرة 256 bit في fragment، فلا يُرسل مع طلب الصفحة أو كجزء من referrer. الواجهة تبعثه في `X-KnowLM-Share` إلى `/v1/shared/view` أو `/v1/shared/grade`، وليس query/path أو رمز جلسة المستخدم. تُحفظ SHA-256 للرمز فقط في القاعدة، ويُعاد الرمز الخام مرة عند الإنشاء. لا تعرض قائمة المالك الرموز مجددًا بعد إعادة التحميل؛ أنشئ رابطًا آخر وألغِ القديم إذا ضاع.

يجب استخدام HTTPS، وعدم تسجيل أجسام طلبات الإنشاء/استجاباتها أو header القدرة في البروكسي والتحليلات. يبقى الرابط نفسه في سجل المتصفح وقد يراه من تشاركه معه؛ fragment ليس تشفيرًا أو حماية من إضافات المتصفح أو screenshots. لا توجد خدمات تحليلات خارجية في صفحة المشاركة الحالية.

استجابات القراءة والتصحيح تحمل `Cache-Control: no-store` و`X-Robots-Tag: noindex, nofollow`؛ صفحة الزائر تضيف robots meta. هذه توجيهات وليست منعًا تقنيًا للنسخ أو فهرسة محرك يتجاهلها. النص يعرض عبر React دون HTML من المصدر.

## الإلغاء والحذف والاحتفاظ

تُعرض آخر 100 مشاركة للدفتر في لوحة المشاركة، مع تاريخ الصلاحية وزر الإلغاء. الإلغاء يتطلب تأكيدًا، يوقف القراءة والتصحيح، ويمحو نص النسخة النشطة مع الإبقاء على metadata للمالك. كل رابط غير صالح أو منتهٍ أو مُلغًى يرجع الخطأ العام نفسه دون كشف عنوان النسخة.

تعديل البطاقات الأصلية لا يعدل نسخة منشورة. حذف الدفتر أو الحساب يحذف سجلات مشاركاته داخل transaction الحذف نفسها، وتُرفض الروابط بعد ذلك. لو تراجع الحذف بسبب خطأ ترجع المشاركات مع بقية البيانات. **لا يمحو الإلغاء أو الحذف نسخة قرأها الزائر بالفعل أو نصًا في ذاكرة تبويبه، ولا النسخ الاحتياطية أو WAL.** إعادة التحقق/التحميل تراجع الخادم وتزيل النسخة من الواجهة إذا لم تعد متاحة. النص المنتهي يحتفظ به في DB حتى إلغاء النسخة أو حذف الأصل؛ يلزم وضع سياسة تنظيف قبل الإطلاق.

## API والترحيل

- `GET /v1/decks/{id}/share-preview` أو `/v1/quizzes/{id}/share-preview`: لصاحب الدفتر فقط، يعيد نسخة منقحة و`preview_hash`.
- `POST .../{id}/shares`: العنوان والصلاحية و`consent=true` وهاش المعاينة؛ يعيد المعرف والرمز الخام والانتهاء مرة واحدة.
- `GET /v1/notebooks/{id}/shares`: قائمة المالك دون رموز أو محتوى.
- `DELETE /v1/shares/{share_id}`: إلغاء للمالك، ويمكن إعادته بأمان.
- `GET /v1/shared/view` بالـheader الخاص: قراءة بلا تسجيل دخول؛ مفتاح التصحيح غير موجود في استجابة الاختبار.
- `POST /v1/shared/grade` بالـheader و`answers` كمصفوفة indices صحيحة: تصحيح خادمي دون حفظ محاولة.

طبّق `alembic upgrade head` (الترحيل `d9489427a65b`) قبل إعادة تشغيل API. ترجيعه يحذف النسخ المشتركة، فخذ نسخة احتياطية وسياسة احتفاظ مناسبة. لا يوجد تكامل اجتماعي أو تقرير إساءة/إشراف/حظر حاليًا؛ **هذه عوائق للنشر العام** وليست خصائص مكتملة ضمن هذه الدفعة.

اختبارات SQLite تغطي الملكية والموافقة وتغير المعاينة وثبات النسخة وتنقيح metadata والصلاحية والإلغاء وحذف الأصل والتراجع والحصص. اختبارات React تغطي المعاينة والموافقة وعرض الزائر وعدم إرسال جلسة المستخدم والنص كبيانات لا HTML. اختبارا Chromium ينشران بطاقات واختبارًا ويفتحانهما في سياق زائر مستقل، ثم يصححان ويلغيان الرابطين على الهاتف والكمبيوتر. PostgreSQL وعمليات إشراف واقعية وحمل عام لم تُختبر.
