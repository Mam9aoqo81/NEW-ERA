# الصوت المحلي والأرشفة وسؤال الاستماع — 0.22

هذا تحديث وظيفي لمسار الصوت: المعاينة تعمل الآن بمحرك كلام محلي حقيقي، وليست مجرد endpoint معطل أو أصوات متصفح غير متاحة. لا يعني ذلك إغلاق جميع المواصفات الأصلية أو الوصول إلى 90% من المتبقي. خصائص التطبيقات الأصلية والفيديو والغرف وخط اليد والجاهزية الإنتاجية مستقلة ولم تُنفذ بهذا التحديث.

## التوليد المحلي

من أدوات المراجعة ← مخرجات الدراسة ← حوار مراجعة صوتي اقتباسي. أنشئ من مصادر محددة ثم وافق على التوليد المحلي. النص يظل سؤال محاور ثابتًا وقراءة اقتباس؛ ليس حوارًا تعليميًا مؤلفًا أو ترجمة. لا يُنشر للمجتمع تلقائيًا.

```sh
.venv/bin/pip install -r backend/requirements-audio.txt
.venv/bin/alembic upgrade head
# بعد إيقاف API القديم، شغله من الجذر:
KNOWLM_TTS_ENABLED=1 KNOWLM_TTS_MODE=local KNOWLM_AUTO_SCHEMA=0 \
  .venv/bin/uvicorn knowlm.asgi:app --app-dir backend --host 0.0.0.0 --port 8000
```

المتغيرات لا تُقرأ من .env تلقائيًا. اضبط إعدادات OCR وغيرها كما في دليل التشغيل. الصوت المحلي لا يحتاج مفتاحًا أو اتصالًا خارجيًا وقت الطلب؛ المكتبة والبيانات تُثبت مسبقًا. المزود الخارجي السابق باقٍ باختيار `KNOWLM_TTS_MODE=provider` وبإعداداته السرية. mode غير معروف يفشل عند بدء الخدمة بدل اختيار مزود خارجي بصمت. الافتراضي العام غير مفعل؛ المعاينة الحالية شُغّلت محليًا صراحةً.

- مكتبة eSpeak NG المرفقة بالحزمة `espeakng-loader==0.2.4`، إصدار المحرك المرصود محليًا 1.52.0. كلام اصطناعي واضح الهوية الآلية، وليس نسخ صوت شخص أو ادعاء أصوات بشرية.
- دور المحاور يستخدم variant m1 والقارئ f2. الكشف البسيط: وجود حروف عربية يختار ar وإلا en-us. لا نضمن جودة النص المختلط أو اللهجة المصرية/الخليجية/الشامية. لا تسميات لهجات زائفة.
- المخرجات PCM mono/16-bit/22050 Hz، مع توقيت الأدوار من العينات. التوليد يتم في child process منفصل لكل دور، لا ctypes داخل خادم الطلبات. حدود Linux: ذاكرة 512 MiB وCPU 15 ثانية وحد ملف 16 MB، مع مهلة parent. الحدود ليست container sandbox أو منع شبكة على مستوى النظام. اختُبر Linux x86-64 فقط، رغم توفر wheels لأنظمة أخرى.
- توجد ملفات مؤقتة مجهولة الاسم من TemporaryFile لخرج child وتُغلق فور قراءتها. ليس «بدون أي أثر قرصي» أو محوًا تشفيريًا؛ سياسات النظام/الذاكرة/swap والنسخ الاحتياطية تحتاج مراجعة إنتاجية.

## حفظ التسجيل واستعادته

خانة موافقة **مستقلة** «أوافق على حفظ التسجيل…» ترسل `save:true` عند التوليد. دونها يبقى الملف مؤقتًا في المتصفح كما في 0.21. حفظ اختياري في جدول audio_recordings، **خاص بمالك الدفتر فقط**، حتى لو كان نص الحوار متاحًا لأعضاء الدفتر. لا S3 أو تشفير تطبيق خاص في هذا الإصدار؛ استخدم تشفير التخزين وصلاحيات DB المناسبة للإنتاج.

- تسجيل واحد لكل مخرج، بحد 5 تسجيلات و32,000,000 بايت لكل دفتر، بالإضافة لحد الملف الواحد 16 MB. لا يسمح بإعادة توليد فوق تسجيل محفوظ قبل حذفه. preflight يرفض حصة ممتلئة قبل استدعاء المحرك؛ الحجم النهائي أو طلب متزامن قد يسبب رفضًا بعد التوليد. المزود الخارجي قد يحاسب العمل حتى لو تعذر الحفظ.
- استعادة الملف لا تستدعي TTS ولا تستهلك حصة التوليد. الحذف كذلك ضمن حد الكتابة العام فقط. التوليد نفسه بحد افتراضي 3 POST/دقيقة لكل هوية حسب نظام LIMITS.
- التسجيلات الخمسة ذات المخرجات القديمة تُقدّم في قائمة المخرجات للمالك حتى لا تختفي خلف حد آخر 30 مخرجًا وتصبح الحصة غير قابلة للتحرير.
- «مسح الصوت المؤقت» يحرر Blob فقط. «حذف التسجيل المحفوظ» يحتاج تأكيدًا ويمحو صف DB ثم يزيل الملف المحلي. لا يمحو الملفات المنزلة أو النسخ الاحتياطية. حذف الدفتر/الحساب يمحو تسجيلاته النشطة قبل المخرجات الأم في transaction نفسها.
- `GET /v1/study-artifacts/{id}/audio/status` يرجع saved/bytes دون تحميل binary. `GET .../audio` يستعيد الملف والتوقيت. `DELETE .../audio` يمحو التسجيل. الجلسة وملكية الدفتر مطلوبة في الثلاثة. الاستجابات no-store. `POST` القائم يقبل `{consent:true,save:false}`؛ حفظ افتراضي false.
- الترحيل `c6ad94578fb7` يأتي بعد ترحيل اللوحة؛ downgrade يسقط التسجيلات فقط. أوقف API عند الترقية وأعد تشغيله بعدها.

## السؤال أثناء الاستماع

قسم مستقل داخل الحوار: التركيز على السؤال أو بدء الإملاء يوقف الصوت. السؤال يُراجع ثم يُرسل بزر صريح إلى مسار ask القائم بوضع extractive وبمعرفات المصادر المختارة فقط؛ لا توليد خارجي ولا embeddings. السؤال والنتيجة في **سجل محادثة الطالب الخاص**، وليس تعليقًا عامًا. إعادة محاولة طلب فاشل تحتفظ request_id للنص واختيار المصادر نفسيهما.

- Web Speech Recognition اختياري عند توفره في secure context، بموافقة منفصلة لأنه قد يعالج الميكروفون عبر خدمة المتصفح خارج الجهاز. ليس ASR محليًا. لا يبدأ تلقائيًا ولا تُرسل نتيجة التعرف كطلب سؤال تلقائيًا. رفض الإذن أو غياب الدعم يترك السؤال النصي متاحًا.
- لا يرفع KnowLM ملف الميكروفون أو يحتفظ به؛ نص السؤال لا يُحفظ إلا بعد الإرسال. لا يعني ذلك عدم احتفاظ خدمة المتصفح بالصوت؛ راجع سياستها.
- الإغلاق أو سحب الموافقة يوقف التعرف ويلغي callbacks. الاستئناف **يدوي**: WAV يحتفظ بموضعه، بينما قراءة المتصفح تعيد الدور من أوله. لا استماع متزامن دائم، ولا جلسة Realtime ثنائية الاتجاه أو إجابة صوتية تلقائية.

## دليل الاختبار وحدود القبول

الجولة الأخيرة: 230 Backend ناجحًا وواحد متخطى، 61 Frontend، **30 متصفحًا ناجحًا** على الكمبيوتر والهاتف. شملت إعادة Backend الأخيرة اختبار أولوية التسجيلات القديمة؛ جولة المتصفح الكاملة سبقت هذا التعديل الدفاعي المحدود. اختبارات المحرك المحلي تولد WAV عربيًا وإنجليزيًا بكلا الصوتين وتتحقق من الطاقة غير الصفرية واختلاف PCM؛ اختبارات المتصفح تولد بالمحرك الحقيقي وتحفظ وتعيد التحميل وتستعيد وتوقف الصوت لسؤال موثق ثم تحذف التسجيل. ليست عينات صامتة في المسار الجديد؛ اختبارات PCM الصامتة القديمة ما زالت تستخدم لاختبار decoder فقط.

لا توجد مراجعة سمعية بشرية مستقلة أو اختبارات مصطلحات/لهجات على أجهزة فعلية. واجهة الإملاء اختُبرت بمحاكاة API؛ مسار السؤال النصي اختُبر مع backend حقيقي، ولم يُختبر ميكروفون فعلي. الاختبارات لا تثبت طبيعية الصوت أو دقة التعرف على الكلام. CI عُدّل لتثبيت الاعتماد الاختياري وتشغيل الاختبار المحلي؛ نجاحه البعيد غير مثبت حتى الآن.
