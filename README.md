# KnowLM · 0.7 — بطاقات واختبارات ومراجعة مرتبطة بالمصادر

تطبيق ويب عربي RTL متجاوب للدراسة من مصادر خاصة، مع Backend بـFastAPI. الواجهة الحالية React + TypeScript + Vite، وليست تطبيق iOS/Android أصليًا بعد. توليد الإجابات متاح اختياريًا عبر مزوّد متوافق مع OpenAI، ومعطّل افتراضيًا.

## المتاح الآن

- أدوات مراجعة: بطاقات يدوية واقتباسية قابلة للتحرير، جدولة SM-2 لكل طالب، اختبارات بتصحيح خادمي ونتائج محفوظة، ودليل/موجز/أسئلة مقاطع/تسلسل سنوات اقتباسي. انظر [دليل أدوات الدراسة](docs/LEARNING.md).

- واجهة عربية للهاتف والويب: حسابات، دفاتر، مصادر، محادثة محفوظة، قارئ استشهادات نصي، ووضع تركيز يخفي تنقل الدفاتر.
- رفع PDF ومتابعة حالته وإعادة محاولة معالجته من الواجهة، أو إضافة نص مباشرة.
- اختيار مصادر السؤال وإظهار الفرق بين البحث المحلي والتوليد الخارجي.

- حسابات وجلسات مدتها 24 ساعة قابلة للإبطال. كلمات المرور مشتقة بـscrypt، ورموز الجلسات محفوظة كبصمات.
- دفاتر ومصادر خاصة مع تحقق الملكية عند الرفع والبحث وقراءة الاستشهاد ومتابعة المهام وإعادة المحاولة.
- نصوص ملصقة وPDF نصي مع الحفاظ على أرقام الصفحات الأصلية.
- روابط YouTube مع نص موقّت SRT/VTT واستشهاد يفتح الفيديو عند توقيت المعلومة. موصّل جلب النص العام موجود لكنه غير مختبر حيًا بسبب قيود الشبكة؛ في المعاينة يعمل مسار النص المرفق صراحةً.
- ترتيب بحث عربي/إنجليزي يجمع BM25 والتشابه الحرفي مع استشهادات وروابط API محمية.
- طبقة توليد اختيارية بصيغة JSON مقيدة، مع رفض الإحالات المختلقة والاقتباسات غير الموجودة.
- مجموعة تقييم محلية من 22 سؤالًا بالعربية والإنجليزية تشمل حالات عدم وجود إجابة.
- طابور PDF دائم في قاعدة البيانات، عامل منفصل، محاولات محدودة واستعادة مهام العامل المتعطل.
- استخراج PDF في عملية فرعية بحد ذاكرة 512 MiB وCPU قدره 20 ثانية ومهلة جدارية 30 ثانية (Linux).
- ترحيلات Alembic، وإعداد Docker Compose اختياري لـPostgreSQL مع امتداد pgvector.

**الوضع الافتراضي استخراجي (`mode=extractive`):** يعمل محليًا دون مفاتيح. لا توجد embeddings أو عملية بحث متجهي بعد؛ الدمج الحالي معجمي بين BM25 والتشابه الحرفي، وليس استرجاعًا دلاليًا. امتداد pgvector غير مستخدم في البحث بعد. لا تغادر المصادر الخادم إلا بطلب `mode=grounded` مع تفعيل مزوّد LLM من إعدادات المشغل. انظر [دليل RAG](docs/RAG.md) للتفعيل والقيود.

## تشغيل الواجهة

شغّل الـAPI وعامل PDF حسب التعليمات التالية، ثم افتح طرفية ثالثة (Node.js 22+):

```bash
cd frontend
npm ci
npm run dev -- --port 5173
```

افتح `http://localhost:5173` على جهاز التطوير، أو معاينة **KnowLM — مساحة الدراسة** في Arena. الطلبات من المتصفح تستخدم مسارات نسبية؛ خادم Vite يمرر `/v1` و`/health` إلى الخادم الداخلي على المنفذ 8000. لا يوجد عنوان localhost مضمن في كود المتصفح. ملفات الخط العربي محلية ضمن الحزمة ولا تعتمد على Google Fonts.

للبدء: أنشئ حسابًا ← أنشئ دفترًا ← أضف نصًا أو PDF ← حدد المصدر ← اطرح السؤال ← اضغط بطاقة المرجع. يمكنك إضافة نص تعليمي تجريبي بزر واضح؛ لا تُنشأ حسابات أو دفاتر أو مصادر تلقائيًا. رسومات شاشة الدخول توضيحية وليست بيانات لحساب حقيقي.

**حفظ المحادثات:** تُحفظ الأسئلة والإجابات المكتملة واستشهاداتها في قاعدة البيانات، وتعود عند تبديل الدفتر أو تحديث الصفحة. يُحمّل السجل على دفعات من 40 رسالة مع إمكانية تحميل الأقدم، ويمكن مسحه بتأكيد دون حذف المصادر. السجل أرشيف للأسئلة، وليس سياقًا يُرسل تلقائيًا للنموذج؛ كل سؤال يبحث مستقلًا في المصادر المحددة. الأسئلة التي سبقت الإصدار 0.5 ولم تكن محفوظة لا يمكن استعادتها. يُحفظ رمز الجلسة في `sessionStorage` لهذه التبويبة، وليس `localStorage`. هذا مناسب للتطوير، وليس بديلًا عن تصميم مصادقة إنتاجي مقاوم لـXSS. لا تُعرض الإجابات كـHTML خام.

انظر [دليل الواجهة والاختبارات](docs/FRONTEND.md)، و[تفاصيل سجل المحادثات](docs/HISTORY.md)، و[دعم YouTube وحدوده](docs/YOUTUBE.md). تُتابَع جميع المواصفات الأصلية في [مصفوفة المتطلبات](docs/REQUIREMENTS.md)؛ لم يكتمل المنتج بجميع خصائصه بعد.

**للترقية من 0.4 أو 0.5:** أوقف الـAPI مؤقتًا، نفّذ `alembic upgrade head` على قاعدة البيانات نفسها، ثم أعد تشغيل الـAPI. الترحيلات تضيف سجل المحادثات وحقول الروابط والتوقيت دون حذف دفاترك أو مصادرك. أعد تشغيل عامل المعالجة أيضًا ليتمكن من معالجة مصادر YouTube.

### تجربة YouTube

اختر **إضافة مصدر ← YouTube**. في المعاينة الحالية أضف الرابط وترجمة موقّتة تملك حق استخدامها بصيغة SRT أو VTT، ثم انتظر اكتمال المعالجة واسأل عن النص. ستعرض الاستشهادات نطاقًا زمنيًا ورابطًا يفتح الفيديو عند بدايته، مع وسم واضح للنص المضاف يدويًا. لم تُختبر صحة مطابقة النص اليدوي للفيديو.

الجلب التلقائي للنص من YouTube غير مفعّل في المعاينة بسبب سياسة الشبكة. اضبط `KNOWLM_YOUTUBE_FETCH_ENABLED=0` في API والعامل في البيئات المقيدة. في بيئة تسمح بالشبكة يمكن تفعيله بـ`1` واختباره؛ توفر النص وموافقة المنصة لا يضمنهما الرابط وحده. راجع YOUTUBE.md قبل التفعيل.

## تشغيل Backend جديد — SQLite

يتطلب Python 3.11+ على Linux. شغّل الأوامر من جذر المستودع:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
alembic upgrade head
KNOWLM_AUTO_SCHEMA=0 uvicorn knowlm.asgi:app --app-dir backend --host 0.0.0.0 --port 8000
```

وفي طرفية ثانية، مع تفعيل البيئة الافتراضية ومن الجذر نفسه:

```bash
PYTHONPATH=backend python -m knowlm.worker
```

لمعالجة مهمة واحدة فقط:

```bash
PYTHONPATH=backend python -m knowlm.worker --once
```

قاعدة SQLite الافتراضية: `backend/data/knowlm.db`، مستبعدة من Git. يجب استخدام قاعدة البيانات نفسها في API والعامل. يغيّر `KNOWLM_DATA_DIR` مسار بيانات التطبيق والعامل؛ عند استخدامه مع Alembic، اضبط `DATABASE_URL` أيضًا لأن Alembic لا يقرأ هذا المتغير.

### ترقية قاعدة نسخة 0.1 الموجودة سابقًا

خذ نسخة احتياطية أولًا. إذا كانت القاعدة تحتوي جداول النسخة 0.1 الأصلية **ولا تحتوي `alembic_version`**، سجّل خط الأساس الموجود ثم طبّق الترحيلات الجديدة:

```bash
alembic stamp 05f8dbbe542a
alembic upgrade head
```

لا تستخدم `stamp` على قاعدة فارغة، ولا على مخطط مختلف دون مراجعته. الترحيل الأول ينشئ المخطط الأصلي، والثاني يضيف جدول المهام، والثالث يفعّل امتداد vector على PostgreSQL فقط. `KNOWLM_AUTO_SCHEMA=0` يمنع الإنشاء التلقائي في التطبيق؛ الوضع الافتراضي المساعد للتطوير لا يغني عن Alembic.

## تجربة كاملة عبر `/docs`

1. `POST /v1/auth/register` ثم `POST /v1/auth/login`. اسم المستخدم لاتيني من 3 أحرف على الأقل وكلمة المرور من 10 أحرف على الأقل.
2. انسخ `access_token` إلى **Authorize**.
3. أنشئ دفترًا من `POST /v1/notebooks` بجسم `{"title":"الأحياء"}`.
4. ارفع ملفًا من `POST /v1/notebooks/{id}/sources/pdf-jobs`.
5. يعيد الرفع **202** مع `id` للمهمة و`source_id` و`status_url`.
6. تابع `GET /v1/jobs/{id}` حتى `completed` أو `failed`. يجب أن يكون العامل قيد التشغيل.
7. عند الفشل، يظهر `error_code` آمن، مثل `ocr_required` أو `unreadable_pdf`.
8. `POST /v1/jobs/{id}/retry` يعيد المهمة الفاشلة للطابور فقط، بحد أقصى ثلاث محاولات إجمالًا. الملف غير المدعوم يحتاج استبدالًا وليس مجرد إعادة محاولة.
9. اسأل من `POST /v1/notebooks/{id}/ask` واقرأ المقتطف والاستشهاد.

أو أضف نصًا مباشرة من `/sources/text`:

```json
{"title":"البناء الضوئي","text":"تحدث عملية البناء الضوئي داخل البلاستيدات الخضراء."}
```

ثم اسأل:

```json
{"question":"البناء الضوئي"}
```

- إغفال `source_ids` يبحث في جميع المصادر الجاهزة بالدفتر.
- `source_ids: []` لا يبحث في أي مصدر.
- تمرير مصدر من دفتر آخر يُرفض بـ404.
- روابط الاستشهاد تحتاج Bearer token نفسه، وليست روابط عامة.
- النص الملصق يستخدم الصفحة 1 كموضع اصطناعي.
- مسار `/sources/pdf` المتزامن القديم باقٍ للتوافق، لكنه يستخدم العملية الفرعية المحدودة أيضًا. يُفضل المسار غير المتزامن الجديد.

## دورة المهمة والموثوقية

```text
pending → processing → completed
                     ↘ failed → retry → pending
```

يحجز العامل المهمة بتحديث شرطي ذري ورمز lease لمدة 90 ثانية. إن تعطل، يمكن لعامل لاحق استعادة المهمة بعد انتهاء المهلة. تمنع مقارنة رمز الحجز العامل القديم من نشر نتائج بعد انتقال الحجز. نشر المقاطع وتحديث حالة المصدر والمهمة يتم في معاملة واحدة. تُحذف حمولة PDF من قاعدة البيانات بعد النجاح، وتبقى عند الفشل لإعادة المحاولة؛ لا توجد سياسة تنظيف تلقائي للمهام الفاشلة بعد.

الطابور قائم على قاعدة البيانات بدل Redis في هذه المرحلة لتقليل المتطلبات التشغيلية. مهيأ للتجارب الصغيرة وليس بديلًا عن منصة مهام واسعة النطاق.

## PostgreSQL + pgvector اختياريًا

```bash
cp .env.example .env
# عدّل POSTGRES_PASSWORD في .env قبل التشغيل
# Docker Compose يقرأ .env تلقائيًا، لكن Python وAlembic لا يقرآنه تلقائيًا.
docker compose up -d db
export DATABASE_URL='postgresql+psycopg://knowlm:YOUR_URL_ENCODED_PASSWORD@127.0.0.1:5432/knowlm'
alembic upgrade head
KNOWLM_AUTO_SCHEMA=0 uvicorn knowlm.asgi:app --app-dir backend --host 0.0.0.0 --port 8000
```

صدّر `DATABASE_URL` نفسه في طرفية العامل. قاعدة البيانات مربوطة محليًا فقط على `127.0.0.1:5432`، ولا يتصل بها المتصفح مباشرة. تفعيل extension يحتاج صلاحية مناسبة؛ لا يسقط ترحيل التراجع الامتداد لأنه قد يكون مشتركًا مع جداول أخرى.

**لم يُختبر تشغيل PostgreSQL/Compose في بيئة التطوير الحالية لعدم وجود Docker.** اختبارات الترحيل والتطبيق تُنفّذ على SQLite؛ يلزم اختبار تكاملي على PostgreSQL قبل اعتماده.

## الاختبارات

```bash
PYTHONPATH=backend pytest -q backend/tests
PYTHONPATH=backend python -m knowlm.evaluate --check
```

تغطي الاستشهادات والرفض وتحديد المصادر وعزل المستخدمين والمصادقة وحدود الملفات وصفحة PDF الثانية. تشمل اختبارات المهام الاستمرار وإعادة المحاولة واستعادة الحجز المنتهي ومنع نشر العامل القديم، إضافة لترقية وترجيع المخطط وفحص مطابقته لنماذج SQLAlchemy. تختبر طبقة التوليد عبر مزوّد اختباري وHTTP محاكى: رفض المراجع المختلقة، وعدم إرسال المصادر غير المحددة، وأخطاء الخدمة والمخرجات غير الصالحة. لا تتصل الاختبارات بمزوّد فعلي.

## حدود الإنتاج والأمان

هذه نسخة تطوير: **لا تستخدم ملفات حساسة أو تعرضها كخدمة عامة قبل المراجعة الأمنية**.

- حدود الملف: 10 MiB و200 صفحة و500 ألف محرف مستخرج. لا يوجد OCR بعد.
- حدود العملية الفرعية ليست sandbox أمنيًا كاملًا؛ يلزم عزل حاوية دون شبكة وصلاحيات ملفات ضيقة، وحدود رفع وتزامن على مستوى الخدمة.
- PDF محفوظ مؤقتًا كحمولة خاصة في قاعدة البيانات، وليس في S3. لا يوجد عارض للملف الأصلي أو إبراز إحداثياته، فقط مقاطع نصية قد تتداخل.
- لا توجد حصص تخزين أو rate limiting أو تنظيف حمولة فاشلة أو استعادة كلمات مرور أو تحقق بريد أو إدارة قُصّر أو مسار حذف كامل بعد.
- البحث يحمّل مقاطع الدفتر إلى الذاكرة. لا يوجد بحث دلالي أو تحقق من استلزام الاقتباسات للادعاءات بعد. التحقق الحالي من وجود الاقتباس ومصدره فقط.
- لا يوجد بعد مجتمع أو صوت أو تعاون أو تطبيقات هاتف أصلية أو ذاكرة محادثة سياقية للنموذج.
- الإنتاج يحتاج HTTPS وإدارة أسرار ومراقبة ونسخًا احتياطية ومشرف عمليات للعامل.

## التالي

1. اختبار PostgreSQL فعليًا وإضافة تخزين خاص للملفات وسياسات حذف وحصص.
2. توسيع مجموعة التقييم إلى ملفات حقيقية مرخّصة وأسئلة إعادة صياغة وحالات تعارض وحقن تعليمات.
3. embeddings وفهرسة متجهية دائمة واختبارات استلزام الادعاءات للأدلة، واختبار مزوّد LLM فعليًا.
4. تطوير جودة التوليد التعليمي والتصدير والإشعارات، ثم المشاركة الاختيارية الآمنة دون كشف المصادر الخاصة.
